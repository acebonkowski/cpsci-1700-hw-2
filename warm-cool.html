Why start with Red, Green, and Blue? Because that's genuinely all a computer ever has to work with — a color is just three numbers to it. Before we can talk about "warm" or "cool," it helps to see those three numbers for yourself.

Step 0 Warm-up

What is RGB?

Every color on a screen is stored as three numbers from 0 to 255: how much Red light, how much Green light, and how much Blue light are mixed together. Slide each one and watch the picture and the numbers move together.

Color values
R 120 G 90 B 200

A computer never sees "purple" or "sky blue" — only three brightness numbers like these. Everything later in this lesson is built on that idea.

Why 0–255?

Black-and-white photos need only one number per pixel — 0 for black, 255 for white, and shades of gray in between. Color needs three — one channel each for Red, Green, and Blue — but it's the same trick: 0 to 255, the 256 values a computer can fit in a single byte. Mixing three of those numbers is exactly how every swatch in this lesson gets its color.

How does training choose the cutoff?

Each color's score is just Red − Blue (from −255 to 255). This tiny model checks every whole-number cutoff in that range — 511 of them — and counts how many labels it would get wrong. The animation samples that search so you can watch it happen.

Real deep-learning models can't just try every possibility — a digit-recognizing model can easily have 784 weights, one per pixel, so checking every combination would take forever. Those models use calculus (gradient descent) to feel out which direction to nudge each weight. Our model only has one number to search, so it skips the calculus and just brute-forces the answer — that's only possible because the search space here is tiny.

The evidence, not just the answer

What does the model actually remember?

After training, the model throws away all 10 colors you labeled. It keeps exactly one number: the cutoff. Every prediction — including the one above — comes from this:

function predict(red, blue) {
  const score = red - blue
  return score >= cutoff ? "warm" : "cool"
}

A classifier can compare things in lots of ways — for example by comparing two distances: is_3(x) = distance(x, typical_3) < distance(x, typical_7), picking whichever is smaller. Ours compares one score to one stored threshold instead. In machine-learning terms, the cutoff is a parameter — a number the model learns once and then keeps forever. The score you compute right now for your slider color is different: it's an activation, a fresh number recalculated every time you move a slider.

Big idea

Two numbers, one guess.
